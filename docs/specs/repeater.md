# QQ 群复读机功能规格

> 状态：已实现。

## 目标

仟仟自用插件在 QQ 群内识别由不同成员形成的连续复读队列，并按配置概率原样参与一次。功能不调用 LLM，也不生成或改写复读内容。

## 配置

新增 `[repeater]` 配置分组，只公开以下字段：

| 字段 | 默认值 | 规则 |
| --- | --- | --- |
| `enabled` | `false` | 单独启用复读功能，避免插件升级后在已有群中突然生效 |
| `repeat_probability` | `0.5` | 每条队列的参与概率，范围 `0.0～1.0` |
| `enabled_group_ids` | `[]` | 空列表表示所有 QQ 群；非空时仅允许列出的群号 |

配置支持 MaiBot 热更新。更新复读配置时清空内存中的队列状态，避免新旧规则混用。

第一版使用以下内置规则，不增加配置项：

- 复读门槛：`2` 个不同成员。
- 相邻消息最大间隔：`120` 秒。
- 内容最大长度：`100` 个 Unicode 字符。
- 同一队列最多参与一次。
- 不设置群冷却。

## 消息范围

仅处理 NapCat 接入的 QQ 群消息。私聊、其他平台、机器人自身消息和未启用群的消息均不改变队列状态。

可复读消息允许按原顺序混合：

- 文本，包括文本中的 Unicode Emoji。
- 包含有效二进制数据、当前 NapCat 与 Host 能够重新发送的 QQ 表情或动画表情。

以下消息不参与复读，并结束当前群已有队列：

- 以 `/` 开头的命令，以及本仓库完整匹配的 `头衔 <内容>` 命令。
- 包含 At、回复引用或合并转发的消息。
- 图片、语音、视频、文件及其他富媒体消息。
- 群通知、空消息、解析失败消息和超长消息。

NapCat 将 QQ 原生表情降级为文字时，插件按收到的文字处理；表情没有有效 `binary_data_base64` 时，整条消息视为不可复读，不发送 `[emoji]` 等占位文字。

## 相同内容

相同内容必须具有完全一致的消息段顺序、消息段类型和稳定内容：

- 文本逐字比较，不裁剪或折叠空白，不忽略大小写，也不做 Unicode 或语义归一化。
- QQ 表情比较稳定标识及内容，不把传输用的二进制字段本身作为身份。
- 不调用 LLM 判断两条消息是否相似。

不同成员发送相同内容才增加复读门槛计数。同一成员连续发送不会增加人数，但也不会结束队列。例如 `A、A、B` 连续发送相同内容时，在 B 的消息到达后达到门槛。

任何成员发送不同内容都会结束旧队列；其消息若可复读，则同时成为新队列的第一条消息。机器人自己的普通回复不结束群成员形成的队列。

## 抽签

队列第一次达到两个不同成员时，只进行一次复读抽签：

1. 按 `repeat_probability` 判断是否参与。
2. 未抽中时把该队列标记为已处理，后续成员继续发送相同内容也不再抽签。
3. 抽中后原样复读，发送成功或失败后都把该队列标记为已处理。

## MaiBot 消息管线

当前 MaiBot 主线没有实际发射官方文档建议的 `EventType.ON_MESSAGE`，第一版使用已接入消息管线的 `chat.receive.after_process` 阻塞 Hook。该 Hook 位于命令匹配和常规 LLM 流程之前。

- 未达到门槛或复读抽签未通过时，Hook 继续后续流程。
- 原样复读发送成功时，Hook 终止触发消息的后续流程，避免 Command 或 LLM 再次回复。
- 第一条候选消息仍会正常进入后续流程，因为插件无法预知是否会有第二名成员复读。
- 机器人普通 LLM 回复不改变插件维护的成员复读队列。

纯文本使用 `ctx.send.text`；包含可发送 QQ 表情的消息使用当前 Host 支持的 `ctx.send.hybrid`，并在 Manifest 中声明实际需要的发送能力。

## 状态与并发

- 每个 QQ 群独立保存一条当前队列，群之间互不影响。
- 队列只保存在内存中，不写数据库；插件卸载、禁用或 MaiBot 重启后清空。
- 相邻相同消息超过 120 秒时，旧队列失效，当前消息建立新队列。
- 同一群消息按到达顺序串行更新，避免并发到达导致重复抽签或发送。
- 插件除依赖 NapCat 默认忽略自身消息外，还校验消息发送者与 `additional_config.self_id`，防止自身消息形成循环。

## 失败行为

- 发送失败只写插件日志，不在群内发送错误提示。
- 失败的队列仍标记为已处理，不为后续相同消息重复发送。
- 因为复读并未成功，Hook 放行触发消息，使其可以继续进入正常 Command 或 LLM 流程。
- 消息或表情数据不完整时关闭失败，不猜测或降级发送占位文本。

## 第一版不做

- 单条普通消息的随机偷句。
- 图片、At、引用、转发及其他富媒体复读。
- LLM 生成、改写或选择复读内容。
- 群内管理命令、逐群参数覆盖、冷却时间和状态持久化。
- 维护其他机器人 QQ 号黑名单。

## 验收

- 两个不同成员在同一启用群、120 秒内连续发送严格相同的合格内容时，只进行一次抽签。
- 同一成员重复发送不满足门槛；`A、A、B` 的相同内容在 B 到达时满足门槛。
- 概率为 `1.0` 时必定参与，概率为 `0.0` 时不参与且同队列不重抽。
- 成功复读严格保留文本与可支持 QQ 表情的顺序；同一队列不重复发送。
- 成功发送后触发消息不进入 Command/LLM；未触发或发送失败时继续正常流程。
- 不同内容、超时、命令、At、引用、富媒体和解析失败消息按规格结束队列。
- QQ 私聊、其他平台、未启用群和机器人自身消息不会触发或污染队列。
- 配置热更新与插件卸载会清空队列；多群状态和并发消息不会相互串扰或重复发送。
